# Experiment summary: open red-teaming guardrail (as of 2026-10-13)

## Goal

An open guardrail that decides, for any input to an AI agent, whether to **block** it (harmful request, jailbreak,
prompt injection) and which of 24 **risk** categories it carries. Block labels come from the datasets; risk-category
labels were generated by GLM (`to_gliner.py`). Every result below measures block/allow only: the risk output has
no independent evaluation yet, so no claim is made about it. It should beat TypeSafe's Jev and other decision
models by a clear margin, trained on the datasets' own (gold) labels rather than Jev's, and be compared with Jev,
AWS Bedrock Guardrails and GLM on accuracy, latency and cost.

## Data

- **Sources** (`datasets_spec.py`): 25 public datasets in 7 groups (direct injection, indirect injection, jailbreak
  templates, harmful requests, mixed safety, toxic content, over-refusal). Each dataset's own label is mapped to
  block/allow.
- **Verification** (`verify_glm.py`): GLM 5.3 Flash labelled each prompt blind; on disagreement GLM 5.3 Prime
  decided. Prompts where neither agreed with the dataset label were dropped.
- **Training set** (run 3 onwards): 25,231 candidates → 22,824 kept (90.5%); 20,572 train / 2,252 validation,
  split by prompt hash, no overlap with each other or the benchmark.
- **Added for run 3**: benign-but-sensitive prompts (OR-Bench, CoCoNot, WildGuard adversarial-benign, toxic-chat)
  and 1,519 synthetic benign emails with LLMail-like features, generated by GLM (`gen_benign_emails.py`).

## Internal benchmark (v2) and its flaw

4,222 prompts kept from 5,212 gold-labelled candidates. **GLM removed 19%**, and the removal fell mostly on subtle
attacks (prompt_shield kept 37 of 81 block prompts, deepset 39 of 60, openai_moderation 73 of 97); two datasets
were dropped whole (do_not_answer, OR-Bench hard). GLM also generated the hard benign emails. A model trained on
GLM-verified data agrees with that selection, so **all v2 numbers below are optimistic and tilted against Jev**.
They are valid for comparing our runs with each other, not as final results.

## Findings

1. **Gold labels beat Jev's labels**: run 2 (0.917) vs run 1 (0.851) on the same model.
2. **Benign data halves false blocks**: run 3 cut the false-block rate from 0.107 to 0.049 for 4 points of recall.
3. **A bigger GLiNER does not generalise better**: run 4 (1.19B) had lower validation loss but more false blocks on
   datasets never trained on (over-refusal 0.23 vs 0.10). Validation loss did not predict benchmark false blocks.
4. **Fine-tuned d3-mini (run 5) did best on this filtered benchmark**: on benchmark-only datasets its benign
   prompts were blocked 8.4% of the time (51 of 609) against run 3's 15%, and its indirect-injection recall was
   0.99 (Jev 0.67, Bedrock 0.28). Whether it generalises better is not established: the benchmark is GLM-filtered
   and d3-mini's pretraining data is unknown.
5. **Thresholds** (chosen on the benchmark, so indicative only): run 5 at 0.98 gives recall 0.950 at 1.3% false
   blocks, better than Jev on both. A threshold must be chosen on a separate set before it can be quoted.
6. **Zero-shot baselines on indirect injection**: recall 0.13 (d1), 0.13 (Shieldstral) and 0.91 (d3-mini, with
   10% false blocks on benign emails). Shieldstral blocked 58% of benign harmful-request look-alikes.

## Run 5 details (best model)

- `train_d3.py`: LoRA r=16 on every text-backbone projection (30.5M params) plus d3's 255-way answer readout,
  trained through d3's own inference computation. Startup check: training and inference probabilities match
  exactly (gap 0.00000); a zero-learning-rate export reproduces the original model's scores.
- 1 epoch, 2,572 steps of 8 prompts, 2 h 25 min, 25.4 GiB peak. Exported to `runs/d3-ft/package`.
- d3-mini: 4.54B parameters, Apache 2.0, built on Qwen3.5-4B. Its training data is not published, so some
  benchmark datasets may be in it.

## Next: external evaluation on GuardRate (English)

Decision: rank on HiveTrace's **GuardRate** leaderboard, English only. HiveTrace keeps its eval data and code
internal and has no public submission process; contact is via Telegram (t.me/hive_trace) or the leaderboard
Space. Ranked models are public Hugging Face models that HiveTrace runs.

Built (`guardrate.py`, no GPU used yet):
- A local rebuild of its English datasets from public sources: 28,749 items, 23 datasets, 16 groups, scored with
  its formulas (dataset = harmonic mean of 1-FPR and 1-FNR, group = harmonic mean, integral = geometric mean).
- The leaderboard's published scores (`data/guardrate_published.json`), kept as reference only: they come from
  HiveTrace's private items, labels and inference settings, so they are not comparable with local numbers, and
  GuardRate notes that small ranking differences may not be significant. Rankings use only systems run locally
  on the same items; the published per-dataset scores of Shieldstral and XGuard check the rebuild.
- Runners for run 5, Shieldstral-3B and YuFeng-XGuard-Reason-8B (the leaderboard's #1, English integral 0.800),
  in request and response mode. Shieldstral and XGuard are on the leaderboard, so they check the rebuild
  dataset by dataset.

Rebuild assumptions: S-Eval "small" configs (attack set sampled to 2,000); RTP-LX unsafe when mean Toxicity ≥ 2;
XSafety without its "commonsense" category; HarmBench responses from its human-labelled validation set. Not
rebuilt: the Prompt injection group (English source not public).

Known issues for run 5 on GuardRate:
- **Contamination**: `guardrate.py audit` flags items whose prompt was seen in training, exactly or as a
  near-duplicate (half or more of its 8-word shingles in training prompts, which also catches shared templates):
  1,313 of 28,749 items, led by or_bench_toxic 642, toxicchat 236, beavertails 147 (most likely prompts shared with Aegis, both drawn from
  Anthropic HH-RLHF), s_eval_attack_set 145 (shared templates), aegis 84. Scores are reported on all items and on
  unseen items only (`score --seen`). Datasets never trained on are reported separately as well.
- **Prompt injection is not covered**: GuardRate's injection group cannot be rebuilt, and injection is central to
  the goal. GuardRate is therefore a complementary safety benchmark, not the only one: a separate, frozen injection
  suite with matched benign/attack pairs (same text with and without an injection, e.g. Microsoft BIPIA) is needed.
- **Scorer**: refuses to score when any prediction is missing or not a probability, so failed items cannot
  silently drop out.
- **Response moderation**: 5 of 23 datasets judge model responses; run 5 never trained on responses (scored
  zero-shot with a response question).
- **Licence**: toxic-chat (in training) is CC-BY-NC-4.0, which leaves a released model's commercial status unclear.

Result (local, same items for all; core = 20 datasets that match published scores; unseen = without the 1,313
items seen in training):

and 21 of 23 for XGuard; toxicchat is mis-rebuilt for both. Details in `experiments.md`.

## Review fixes (2026-10-13)

An external review raised six points; all were accepted: injection coverage (separate paired suite),
published vs local comparability (published scores now reference only), contamination beyond OR-Bench (near-
duplicate audit, unseen-only scores), unevaluated risk categories (stated), incomplete predictions (scorer now
refuses them), and two overstated findings (rewritten as measured observations).

## Open decisions for review

1. Next run's target: recall on plain harmful requests (S-Eval, XSafety, Aya, MultiJail style) without losing
   the low false-block rate; compare against XGuard-8B on unseen core items.
2. Accept the GuardRate English rebuild as the safety benchmark, together with a frozen paired injection suite
   (to be built), replacing benchmark v2 and the draft `EVAL.md`.
3. Risk categories: build an independently annotated category eval, or describe the risk output as unevaluated.
4. Next training run (run 6, data and code ready, see `experiments.md`): or_bench_toxic and toxic-chat removed,
   plain harmful requests and response pairs added, everything decontaminated against GuardRate and the internal
   benchmark; checkpoint and threshold chosen on four whole held-out sources with gold labels.
5. Whether and how to approach HiveTrace for an official listing.
6. Clean-up: `adjudicate.py` and a small temperature option in `verify_glm.py` are unused since the GLM
   re-judging plan was dropped.
